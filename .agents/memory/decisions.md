# Architecture & Design Decisions

- **Pure-Go SQLite**: Used `modernc.org/sqlite` with `CGO_ENABLED=0` to keep cross-compilation simple and avoid C runtime dependencies in container images.
- **Go 1.22 ServeMux Patterns**: Leveraged standard library enhanced routing patterns (methods and path wildcards) without external web frameworks.
- **Selective Transcoding**: Applied copy-vs-transcode based on media codecs; H.264 video and AAC audio are copied without re-encoding to minimize CPU usage.
- **Lazy On-Demand Streaming**: FFmpeg processes start lazily on the first manifest request (`.m3u8`) at the calculated wall-clock offset, and are automatically reaped by `SessionManager` when idle.
- **RAM Segment Storage**: Placed `/transcode` on a 1GB `tmpfs` volume to protect SSD wear from high-frequency HLS segment creation and deletion.
- **MAKER Methodology**: Used the MAKER framework (atomised micro-tasks, strict verification gates, red-flag abort conditions) for the initial system construction.
- **Git Flow Branching Model**: Adopted Git Flow (`main` for tagged releases, `develop` for integration, short-lived feature/fix/release/hotfix branches) with `.githooks/pre-commit` enforcement (`gofmt`, `go vet`, `go build`, and blocking direct commits on `main`).
- **2026-10-17 Frontend & Playout Architecture Roadmap**:
  - Embedded React 19 SPA (Vite, TypeScript, Tailwind, Radix, `motion`, TanStack Query) built in multi-stage Docker and embedded via `go:embed` with SPA fallback.
  - Viewer device priority: Desktop/Web > Smart TV (10-foot D-pad) > Mobile.
  - Zero-CPU idle stream: pre-encode static card (`siaran_segera_kembali.jpg`) once with silent AAC; loop via `-stream_loop -1 -re -c copy`. Reaped after 60s idle (not 24/7).
  - Auth & Live Status: Env admin password, HTTP-only cookie, CSRF; SSE at `/api/v1/events` for real-time CMS playout tracking. Deferred browser file uploads (retain `/media` volume ingest).
- **Phase 1 Playout Supervisor & FFmpeg Flags**:
  - Correct HLS discontinuity flag: The FFmpeg flag is `discont_start` (not `discontinuity_start`).
  - Infinite live manifests: `omit_endlist` is always set in `-hls_flags` so live broadcast manifests never terminate with `#EXT-X-ENDLIST`.
  - Explicit stream mapping: `-map 0:v:0 -map 0:a:0? -sn -dn` is strictly used because real MKV containers frequently carry ASS subtitles and font attachments that break HLS muxing.
  - Idle clip 2s keyframes: Idle clip pre-encoding forces keyframes every 2s so the initial HLS manifest appears in ~2s.
  - Zero-CPU idle looping: Idle channels are copy-looped (`-stream_loop -1 -re -c copy`), consuming ~0 CPU overhead.
- **Phase 2 Auth & Playout Decisions**:
  - In-memory skip offset: Playout skip offset is held in-memory only and shifts the supervisor timeline; EPG and M3U feeds continue to compute from wall clock, so their schedule metadata can differ from actual playout after a skip.
  - Direct RemoteAddr rate limiting: The login rate limiter strictly inspects `r.RemoteAddr` and does not trust `X-Forwarded-For` to prevent unauthenticated header spoofing without explicit proxy configuration.
  - Temporary vanilla dashboard auth: Added a minimal login modal to the legacy vanilla dashboard to support authenticated operations until Phase 5 replaces the UI.
  - Repository-wide LF enforcement: Added `.gitattributes` forcing LF endings repository-wide because `core.autocrlf=true` generated CRLF line breaks that broke `gofmt -l` checks during pre-commit.
- **Phase 3 Frontend Scaffold Decisions**:
  - Exact version pins: Configured `.npmrc` with `save-exact=true` and enforced `packageManager` in `package.json` (`pnpm@10.5.2`) for reproducible and deterministic dependency lockfiles.
  - Vite outDir is dist/app: Vite build output is isolated to `web/app/dist/app` so that the tracked placeholder `web/app/dist/.gitkeep` survives Vite's `emptyOutDir`. A clean git clone can immediately run `go build` out of the box without Node installed (bug found and fixed).
- **Phase 4 Viewer Page Decisions**:
  - Exact `hls.js` 1.7.3 pinned and isolated into a dedicated manual vendor chunk (`hls`) in `vite.config.ts` to prevent bloating the main app bundle.
  - Real browser mount timing bug: When `ViewerPage` loads, the video element is only mounted after the asynchronous channel query completes. An initial hook effect using a standard `useRef` ran once when the ref was still `null`, leaving playback uninitialized. Fixed by holding the video element in React state (`videoEl`) so the player effect triggers immediately when the DOM node attaches, backed by a regression test.
  - Verification lesson: Unit tests using a mocked `hls.js` missed the lifecycle timing mismatch entirely because the mock executed synchronously against synthetic DOM nodes; always perform real-browser playback checks.
- **Phase 5 CMS Studio Decisions**:
  - Dependencies added: `@dnd-kit/core` 6.3.1, `@dnd-kit/sortable` 10.0.0, `@dnd-kit/utilities` 3.2.2, and `sonner` 2.0.8, kept isolated in the lazy `admin` chunk in `vite.config.ts`.
  - Minimal stack: No Radix UI or external form libraries added; used native HTML `<dialog>` elements and lightweight controlled forms to avoid runtime bloat.
  - Schedule planner deferred: Visual schedule planner was deliberately not built here because F1 (scheduled broadcast) in the roadmap Future Plan owns calendar slot resolution.
  - Filler management view-only: Filler management is view-only on the System page; idle card generation remains automated server-side.
- **2026-10-17**: Future plan recorded: scheduled broadcast (F1) and realtime analytics (F2), not scheduled yet; see docs/ROADMAP.md.
- **2026-10-17**: Future plan expanded with F3 and F4 (docs/ROADMAP.md):
  - F3 (Public link security and request-flood protection): Priority normal (must precede any public/internet exposure). Mitigates remaining attack surface (unauthenticated HLS manifest/segment routes and lack of rate limiting) via short-lived HMAC-signed stream tokens, per-IP rate limiting (RemoteAddr default, never trust X-Forwarded-For without trusted proxy config), concurrency cap on FFmpeg instances, per-channel start cooldown, 429 Retry-After, and security headers.
  - F4 (Anti-recording / stream protection): Priority LOW (explicitly deprioritised by user decision). Acknowledged technical reality that any stream playable on client hardware can be captured; casual deterrence only (AES-128 encryption with tokenized key delivery, forensic watermarking which sacrifices zero-CPU stream copy); strictly deferred until after F3.
- **Phase 6 Motion System Decisions**:
  - `motion` 14.3.0 exact, imported only in the lazy admin chunk and guarded by a test (`motionGuard.test.ts`) that fails if the viewer imports it.
  - `AnimatePresence` chosen over the View Transitions API (cross-browser, ties to `MotionConfig`, avoids snapshot freezes over live video).
  - Reduced motion precedence: `prefers-reduced-motion` strictly beats a stored `'full'`.
  - Lite heuristic: `hardwareConcurrency <= 4` or `deviceMemory <= 2` is unverified.
  - CSS guard test forbids animating layout props (`width`, `height`, `top`, `left`, `margin`, `padding`), enforcing GPU-composited `transform` and `opacity`.
- **Phase 7 TV UI Decisions**:
  - In-house spatial navigation: Implemented custom geometric/Euclidean distance spatial navigation in `src/lib/spatialNav.ts` with zero external dependencies (avoiding `norigin-spatial-navigation` or heavy third-party packages) to keep viewer bundle size under budget and avoid lifecycle friction with React 19.
  - TV profile detection: Built dual detection via user agent strings (Tizen, webOS, Android TV, etc.) and explicit query parameter (`?profile=tv`) for testing; sets `data-tv="true"` on `<html>` to scale typography, enlarge focus outlines, and enforce safe-area margins.
  - Remote key map: Normalized Smart TV remote keycodes (D-pad arrows, OK, Return/Back, ChannelUp/Down, VolumeUp/Down, 0-9 numeric keypad, color buttons) into semantic actions in `src/lib/remoteKeys.ts`.
  - Volume & mute persistence: Volume and muted states are persisted to `localStorage` (`niracast_volume`, `niracast_muted`) so remounted video elements on channel switches preserve user volume level.
  - TV UI components: Built dedicated 10-foot components (`ChannelRailTv`, `DigitEntryOverlay`, `RemoteLegendModal`, `VolumeToast`) maintaining contrast and high visibility without obstructing video playout.
- **Phase 8 Mobile UI Decisions**:
  - Mobile profile detection & override persistence: `getDeviceProfile` detects mobile profiles via user-agent regex or coarse pointer (`pointer: coarse`) and narrow viewports (<768px). Supports URL parameter overrides `?ui=mobile|tv|desktop` (with backwards compatibility for `?profile=tv`). Stored in `localStorage` under key `'ui'`. Note: Because this override persists in `localStorage` per origin, a desktop browser tested with `?ui=mobile` or `?ui=tv` stays in that mode until explicitly cleared or overridden with `?ui=desktop`. TV detection takes precedence over mobile when both might match.
  - Zero-dependency pure gesture engine: Implemented custom gesture recognition in `src/lib/gestures.ts` (`detectSwipe`, `calculateRubberBand`, `isTap`, `useSwipeGesture`, `useBottomSheetDrag`) using native Pointer Events, transform-only GPU animations, velocity/threshold detection, and reduced-motion compliance without external gesture dependencies.
  - Bottom sheets over side drawers: Transformed `ChannelDrawer` and `ProgramGuideSheet` into interactive mobile bottom sheets with drag handles and touch swipe-down-to-dismiss behavior on mobile viewports, while preserving desktop sidebar drawer layouts on wide screens.
  - Mobile admin ergonomics: Added a fixed bottom navigation tab bar (`AdminBottomBar`) on mobile viewports for quick thumb-reach navigation; refactored Channels and Media data tables into stacked responsive cards (`block md:table`, `block md:table-row`) to eliminate horizontal scroll down to 320px width.
  - Touch drag reordering: Configured `@dnd-kit/core` with `TouchSensor` (250ms delay, 5px tolerance) in `PlaylistEditorPage`, enabling touch drag reordering without conflicting with vertical page scrolling.
  - Mobile video inline playback: Added `playsInline` and `webkit-playsinline` attributes to the viewer `<video>` element, preventing mobile Safari and Android browsers from hijacking playback into native fullscreen, preserving custom HUD overlay controls.
- **Control Room Glass UI Revamp Decisions (2026-10-17)**:
  - Real blur on desktop only (decision change): The earlier Phase 6 rule ("no backdrop-blur over video") is replaced with "real blur on desktop only". `.glass*` classes apply real `backdrop-filter: blur(...) saturate(180%)` on desktop shell chrome (sidebar, top bar, HUD overlay, dialogs), but fall back to solid tinted fills without backdrop-filter on `html[data-ui=tv]`, `html[data-ui=mobile]`, `data-motion=lite|reduced`, `prefers-reduced-transparency`, or when backdrop-filter is unsupported. Content cards use non-blurred `.surface-card`.
  - Viewer always dark: The viewer page (`/watch/:id`) enforces a dark interface at all times via `.scheme-dark` on the root, regardless of user preference, while admin, login, home, and 404 support dark and light themes resolved in `src/lib/theme.ts` (localStorage `theme`, `system|light|dark`) with an inline pre-paint script in `index.html`.
  - Tokens and shared UI primitives: Semantic design tokens and Apple-style materials declared in `src/index.css` with `.glass*` and typography classes in `@layer components` so utilities can override them, and radii/mono font in `@theme`. Standard UI primitives built in `src/components/ui/` (`GlassPanel`, `Button`, `Card`, `StatTile`, `Field`/`Input`/`Select`/`Textarea`, `StatusPill`, `SegmentedControl`, `ThemeToggle`, `EmptyState`, `ChannelArt`) with zero new dependencies, no motion imports, and guarded by `tokenGuard.test.ts`.
  - Vite vendor chunking: `vite.config.ts` `manualChunks` pins only `hls.js`. Removed the explicit `admin` manual chunk because it pulled React, router, and shared code into the admin bundle, causing `/watch` to unnecessarily download motion and dnd-kit while `/admin` downloaded `hls.js`. Relying on native `React.lazy` code splitting keeps `/watch` (index + ViewerPage + mode + hls) and `/admin` (index + AdminPage + mode) strictly isolated.
- **Roadmap F1 Scheduled Broadcast Decisions (2026-10-17)**:
  - Channel mode `loop|scheduled`: Added `mode` column to `channels` table (`CHECK (mode IN ('loop','scheduled'))`, default `'loop'`). Channels operate either as continuous wall-clock loops of their playlist items or as fixed clock-time scheduled slot broadcasts.
  - Dated slots with timezone-aware recurrence: Schedule slots define absolute start timestamps with recurrence rules (`none`, `daily`, `weekly`). Occurrences are expanded in the server timezone configured via `TIMEZONE` env (default `Asia/Jakarta`, DST-safe wall-clock preservation via native Go `time.Date` reconstruction).
  - Overrun cut at slot end: When media duration exceeds configured slot length, playout is strictly truncated at the slot boundary to preserve subsequent programming timings.
  - Gaps show idle slate: Programming gaps between scheduled slots (or trailing time in slots where media is shorter than the slot duration) automatically play the pre-encoded idle slate clip (`siaran_segera_kembali.jpg`).
  - Playout skip disabled in scheduled mode: Playout skip (`POST /api/v1/channels/{id}/skip`) returns HTTP 409 Conflict (`{"error":"skip_unavailable"}`) in scheduled mode, as scheduled broadcasting is pinned to absolute wall-clock time and cannot be artificially advanced.
  - Schema v2 via `PRAGMA user_version`: SQLite schema upgraded to version 2 tracked via `PRAGMA user_version = 2`. Because a full migration runner is not yet implemented, legacy development databases (version 0 with existing channels) are rejected on server startup with a descriptive error instructing a dev reset.
  - Table refactoring: Renamed legacy `schedules` table to `playlist_items` (with backward compatibility view `schedules` and INSTEAD OF triggers), dropped unused `playlists` table, and created `schedule_slots` with index `idx_slots_channel(channel_id, start_at)`.
  - Supervisor Reload on schedule edits: All slot mutations (`POST`, `PUT`, `DELETE` on `/api/v1/channels/{id}/schedule/slots/...`) trigger `supervisor.Reload(channelID)` to immediately re-evaluate the active stream pipeline.
